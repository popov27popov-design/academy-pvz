# Академия ПВЗ — Implementation Specification v1.2

**Основа:** согласованные решения D-101—D-105 и требования единого контекста ТЗ v1.1 от 18.11.2026. Стек и критерии ниже — инженерная спецификация/предложение, не новое бизнес-решение. Цель текущего этапа — R0; в R1 не переходить до закрытия юридических и платёжных блокеров.

## 1. Объём релизов

| Релиз | Включено | Граница готовности |
|---|---|---|
| R0 — технический прототип | Витрина; 3 направления + концепция комплекта; регистрация/вход; БД; один демо-урок; тест; образец PDF и проверка токена | Сквозной маршрут работает на тестовых данных. Оплата и реальные учебные инструкции выключены. |
| R1 — коммерческий MVP | 4 продукта, подтверждённые цены/договорная модель; платежи и идемпотентный webhook; полноценные уроки и версии контента; прогресс; аттестации; сертификаты/отзыв; админка, B2B-заявки и ручные назначения; согласия и юридические страницы | Нет P0/P1; закрыты ISS-01—05; контент источников проверен; сценарии приёмки пройдены. |
| R2 | Самостоятельные места B2B, массовый импорт, расширенные отчёты, подписки, AI, приложение | Только после подтверждения спроса и экономики. |

## 2. Архитектура R0

Одно приложение Node.js с HTTP API, серверным SQLite-файлом для локального прототипа и статическим адаптивным интерфейсом. Коммерческая целевая схема остаётся модульным монолитом: Identity, Catalog, Commerce, Learning, Assessment, Certification, Organizations, Admin. До R1 перейти на PostgreSQL/управляемую инфраструктуру после выбора хостинга и проверки локализации ПД. R0 не считать готовым production-секьюрити.

### Слои

- UI: публичные страницы, формы входа и регистрации, демо LMS, состояния загрузки/ошибки/успеха.
- API: JSON, серверная проверка сессии и владения записью; неизвестный API-маршрут даёт 404.
- Данные R0: `users`, `sessions`, `enrollments`, `progress`, `attempts`, `certificates`.
- Файлы: PDF генерируется сервером; QR содержит только случайный непрогнозируемый токен публичной проверки.
- Учётные данные: пароль хранится как scrypt-хеш с уникальной солью; cookie HttpOnly + SameSite=Lax. HTTPS/Secure, CSRF/origin защита, rate limits, аудит и ротация сессий обязательны до R1.

## 3. Схема данных

| Таблица | Поля и ограничения | Владелец / правила |
|---|---|---|
| User | `id UUID PK`, `email UNIQUE NOT NULL`, `name`, `password_hash`, `created_at` | Email нормализуется в lowercase. В R1 роли отдельно в RoleAssignment. |
| RoleAssignment | `id UUID`, `user_id FK`, `organization_id nullable`, `role`, `created_at` | R1; роли student, org_admin, content_editor, reviewer, admin; проверять на сервере. |
| Organization | `id UUID`, `name`, `created_at` | R1. Организационный пользователь видит только свою организацию. |
| OrganizationMember | `organization_id FK`, `user_id FK`, `role`; unique pair | R1. Не полагаться на фильтр UI. |
| Course / CourseVersion | UUID, slug, platform, status; версия, номер, совместимость ядра, даты | Контент после публикации неизменяем; изменения создают новую версию. |
| Lesson / Module | UUID, version FK, порядок, тип, тело, обязательность, статус | Непроверенное содержание не публиковать. |
| Product / ProductCourse | UUID, SKU, price_minor nullable, currency, active; связи product-course | Тарифы не публиковать, пока цена не утверждена. Комплект ссылается на три курса. |
| Enrollment | UUID, user FK, course/version FK, source, status, `UNIQUE(user_id, course_version_id, source_ref)` | Заказ/ручная выдача; активное назначение не дублировать. |
| LessonProgress | user, lesson/version, status, completed_at; unique pair | Завершение только сервером, относится к версии урока. |
| QuestionVersion | UUID, question family, content, options, answer key, critical, source_ref, approved_by | Ответ и критичность никогда не отдавать клиенту. |
| Attempt / Answer | UUID, user, course_version, started_at, server deadline, submitted_at, score, passed; versioned answers | Сданная попытка неизменяема; таймер только серверный. Лимит повторов пока требует утверждения. |
| Order / OrderItem / Payment | UUID, status, total_minor, provider IDs UNIQUE, event ID UNIQUE, timestamps | Доступ появляется только после проверенного события оплаты. Webhook транзакционный и идемпотентный. |
| Certificate | UUID, user, course_version, attempt, serial UNIQUE, token_hash UNIQUE, status, reason, timestamps | Публичный токен высокоэнтропийный; хранить hash. Отзыв требует причины и аудита. |
| ConsentRecord / AuditEvent | UUID, subject, purpose/action, version, timestamp, actor | Минимизировать ПД; аудит ключевых административных действий. |

R0 сейчас реализует лишь основу User, Enrollment, LessonProgress, Attempt, Certificate и Sessions; таблицы R1 — проектная схема, а не готовый код.

## 4. API-контракты

Ответы ошибок: `{ "error": { "code": "...", "message": "..." } }` для R1; R0 пока возвращает `{error: string}`. Все изменения требуют аутентификации, если явно не помечены public. UUID непрозрачны; чужая запись отвечает 404 либо 403 без раскрытия факта существования.

| Метод / маршрут | Доступ | Вход / результат | Критерий |
|---|---|---|---|
| `GET /api/courses` | public | опубликованный каталог и активные продукты | Черновики не выдаются; цена не подменяется гипотезой. |
| `POST /api/auth/register` | public | email, имя, пароль; пользователь + сессия | Повтор email — 409; валидация; пароль только хеш. |
| `POST /api/auth/login` | public | email/пароль; сессия | Общая ошибка неверной пары; rate limit для R1. |
| `POST /api/auth/logout`, `GET /api/me` | user | уничтожить сессию / свой кабинет | В кабинете только собственные назначения, прогресс, попытки, сертификаты. |
| `POST /api/orders` | user | product IDs, version согласий; заказ PENDING | Не создавать доступ. Сервер повторно вычисляет сумму. |
| `POST /api/payments/webhook` | provider | подписанное событие с уникальным event ID | Проверка подписи, идемпотентность, транзакция order+payment+enrollment. |
| `POST /api/lessons/{id}/complete` | enrolled user | lesson/version | Проверить обязательные предпосылки; сохранить без дублей. |
| `POST /api/attempts` | enrolled user | course version | Только после обязательных уроков; deadline выставляет сервер. |
| `PUT /api/attempts/{id}/answers` | владелец попытки | ответы | Сервер проверяет принадлежность и состояние попытки. |
| `POST /api/attempts/{id}/submit` | владелец попытки | без доверия к клиентскому баллу | Повторный submit не создаёт новую попытку/сертификат. |
| `GET /api/me/certificates` | user | список своих | Только собственные. |
| `GET /api/verify/{token}` | public | token | Минимальные поля, ACTIVE/REVOKED/SUPERSEDED; токен не перечислим. |
| `/api/admin/*` | admin/reviewer/org scope | специфично | Серверный RBAC и audit event; тесты горизонтального/вертикального доступа. |

## 5. Роли и доступ

- Анонимный: публичная витрина, каталог, документы, проверка сертификата.
- Ученик: свой профиль/курсы/прогресс/попытки/сертификаты. Никаких клиентских user_id без серверной проверки владения.
- Представитель организации: сотрудники и назначения только своей организации; в R1 доступ только к базовому прогрессу, без чужих ответов теста.
- Контент-редактор: черновики курсов и вопросов; не может публиковать собственные материалы без роли reviewer.
- Администратор: назначения, заказы, пользователи, сертификаты; отзыв только с причиной, всё в журнале.
- Служебный платежный webhook: только подпись провайдера, без пользовательской cookie.

## 7. R0 acceptance checklist

1. Каталог показывает три направления и комплект без выдуманной цены.
2. Регистрация создаёт аккаунт; вход/выход работают; повторная регистрация сообщает конфликт.
3. Демо-доступ к одному курсу открывает только этот курс; комплект создаёт три назначения без дублей.
4. Незалогиненный пользователь не отмечает урок и не сдаёт тест; тест до урока отклоняется.
5. Завершение урока сохраняется при повторной загрузке страницы.
6. Сервер сам считает результат; критический вопрос с неверным ответом даёт fail независимо от процента.
7. Успешная попытка создаёт один PDF; повторные действия не плодят сертификаты.
8. QR ведёт на публичную страницу проверки с корректным направлением; случайный токен не находит сертификат.
9. Мобильная ширина 320px остаётся читаемой и функциональной.
10. Оплата и коммерческие тексты не представлены как действующие.

## 8. Нерешённые блокеры и допущения

**BLOCKER:** ISS-01 юрлицо/продавец; ISS-02 квалификация обучения/лицензирование; ISS-05 платёж и фискализация. **HIGH:** ISS-03 допустимые актуальные источники инструкций; ISS-04 оферта, возвраты, ПД и согласия. Не включать оплату, публикацию реальных регламентов и массовый сбор ПД до решения. ISS-06 цены/экономика; ISS-07 инфраструктура и локализация; ISS-08 параметры аттестации — остаются вопросами/предложениями.
